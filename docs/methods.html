Gaussian Naive Bayes

Idea

Naive Bayes asks: which income tier makes this spending pattern most likely? It starts with how common each tier is, checks how typical each spending share is for that tier, and picks the tier with the highest combined score.

How it works

It uses Bayes' rule:

P(tier | x)  ∝  P(tier) × P(x₁ | tier) × P(x₂ | tier) × … × P(x₁₀ | tier)
 posterior        prior              likelihoods
  • Prior P(tier): the fraction of training rows in that tier (0.3, 0.4, 0.3).
  • Likelihood P(xⱼ | tier): our features are percentages, not counts, so each feature in each tier is modelled as a bell curve (Gaussian) with that tier's mean μ and variance σ²: 
    P(x | tier) = 1 / √(2πσ²) × exp( −(x − μ)² / (2σ²) )
  • "Naive" assumption: features are treated as independent given the tier, so their likelihoods are simply multiplied.
  • Evidence P(x) is skipped: it is the same for every tier, so it does not change which tier wins.

Multiplying many small probabilities can round down to 0, so we work with logs, which turn the products into sums: 

score(tier) = log P(tier) + Σⱼ log P(xⱼ | tier)
prediction  = the tier with the highest score

How we implemented it

fit() learns a prior, and a mean and variance for every feature, per tier:

for c in classes:
    Xc = X[y == c]                                  # rows of tier c
    priors.append(len(Xc) / len(X))                 # P(tier)
    means.append(Xc.mean(axis=0))                   # μ of each feature
    variances.append(Xc.var(axis=0) + smoothing)    # σ² of each feature

smoothing is the var_smoothing hyperparameter (1e-9): a tiny value added to every variance so it is never 0, since dividing by 0 would break the formula. It plays the same role as additive (Laplace) smoothing for word counts.

log_likelihood() computes the log of the bell curve directly (log(a × b) = log a + log b):

log_coeff    = -0.5 * np.log(2 * np.pi * var)
log_exponent = -((x - mean) ** 2) / (2 * var)
return log_coeff + log_exponent

predict() scores every tier and picks the highest:

log_prior       = np.log(priors[i])
log_likelihoods = log_likelihood(row, means[i], variances[i])   # all 10 features at once
scores.append(log_prior + np.sum(log_likelihoods))
...
predictions.append(classes[np.argmax(scores)])

Pipeline interface: train_nb() wraps fit(), and predict_nb() wraps predict().

Results on the test set

NB does best on the High tier (F1 0.75). Middle has the highest recall (0.71) but the lowest precision (0.61): the model often predicts Middle for rows that are really Low or High, which makes sense since Middle sits between the other two tiers.

Notes and references

  • Gaussian NB is the variant of Naive Bayes for continuous features. Our lab version counted words; here each feature is a bell curve instead.
  • Limitation: the independence assumption does not hold for our data. The 10 shares are parts of one budget, so when one share goes up, others go down.
  • Structure adapted from D. Oniani, ai repository (MIT License), gaussian_naive_bayes.py. Our changes: priors and variance smoothing computed once in fit(); the log of the Gaussian computed directly to avoid log(0).
  • Formula: scikit-learn documentation, Gaussian Naive Bayes (used as a reference only; no scikit-learn code is used).
