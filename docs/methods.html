How each of our three classifiers works, how we implemented it from scratch, and its results on the test set. The side-by-side comparison is in Results.

Gaussian Naive Bayes

Idea

Naive Bayes asks: which income tier makes this spending pattern most likely? It starts with how common each tier is, checks how typical each spending share is for that tier, and picks the tier with the highest combined score.

How it works

It uses Bayes' rule:

P(tier | x)  ∝  P(tier) × P(x₁ | tier) × P(x₂ | tier) × … × P(x₁₀ | tier)
 posterior        prior              likelihoods
  • Prior P(tier): the fraction of training rows in that tier (0.3, 0.4, 0.3).
  • Likelihood P(xⱼ | tier): our features are percentages, not counts, so each feature in each tier is modelled as a bell curve (Gaussian) with that tier's mean μ and variance σ²: 
    P(x | tier) = 1 / √(2πσ²) × exp( −(x − μ)² / (2σ²) )
  • "Naive" assumption: features are treated as independent given the tier, so their likelihoods are simply multiplied.
  • Evidence P(x) is skipped: it is the same for every tier, so it does not change which tier wins.

Multiplying many small probabilities can round down to 0, so we work with logs, which turn the products into sums: 

score(tier) = log P(tier) + Σⱼ log P(xⱼ | tier)
prediction  = the tier with the highest score

How we implemented it

fit() learns a prior, and a mean and variance for every feature, per tier:

for c in classes:
    Xc = X[y == c]                                  # rows of tier c
    priors.append(len(Xc) / len(X))                 # P(tier)
    means.append(Xc.mean(axis=0))                   # μ of each feature
    variances.append(Xc.var(axis=0) + smoothing)    # σ² of each feature

smoothing is the var_smoothing hyperparameter (1e-9): a tiny value added to every variance so it is never 0, since dividing by 0 would break the formula. It plays the same role as additive (Laplace) smoothing for word counts.

log_likelihood() computes the log of the bell curve directly (log(a × b) = log a + log b):

log_coeff    = -0.5 * np.log(2 * np.pi * var)
log_exponent = -((x - mean) ** 2) / (2 * var)
return log_coeff + log_exponent

predict() scores every tier and picks the highest:

log_prior       = np.log(priors[i])
log_likelihoods = log_likelihood(row, means[i], variances[i])   # all 10 features at once
scores.append(log_prior + np.sum(log_likelihoods))
...
predictions.append(classes[np.argmax(scores)])

Pipeline interface: train_nb() wraps fit(), and predict_nb() wraps predict().

Notes and references

  • Gaussian NB is the variant of Naive Bayes for continuous features. Our lab version counted words; here each feature is a bell curve instead.
  • Limitation: the independence assumption does not hold for our data. The 10 shares are parts of one budget, so when one share goes up, others go down.
  • Structure adapted from D. Oniani, ai repository (MIT License), gaussian_naive_bayes.py. Our changes: priors and variance smoothing computed once in fit(); the log of the Gaussian computed directly to avoid log(0).
  • Formula: scikit-learn documentation, Gaussian Naive Bayes (used as a reference only; no scikit-learn code is used).

K-Nearest Neighbors

Idea

K-Nearest Neighbors (KNN) asks: which training rows have the most similar spending pattern? Instead of fitting a formula during training, it compares each test row against every training row, finds the k closest matches, and lets them vote on the income tier.

How it works

It measures similarity using Minkowski distance across all 10 spending shares:

d(x, y) = ( Σⱼ |xⱼ − yⱼ|ᵖ )^(1/p)
  • Minkowski distance (p = 2): sums the feature-wise differences raised to p, then takes the p-th root. With p = 2, this is standard Euclidean distance.
  • Top k neighbors (k = 5): sorts all 830 training rows from smallest distance to largest and keeps the 5 closest rows.
  • Majority vote: counts how many of the 5 neighbors belong to Low, Middle, and High, and picks the tier with the most votes.
  • Tie-breaker: if two or more tiers tie for the highest vote count, it picks the tied tier whose neighbor is closest in distance.

How we implemented it

train_knn() stores the training data and hyperparameters (k = 5, p = 2) in a dictionary—KNN does all its work at prediction time:

def train_knn(X_train, y_train, k=5, p=2):
    return {"X": X_train, "y": y_train, "k": k, "p": p}

minkowski() computes the distance between one training row and one test row across all 10 features:

summation = 0
for i in range(len(testing)):
    summation += abs(training[i] - testing[i]) ** p
return summation ** (1.0 / p)

voting() counts the labels of the k nearest neighbors and breaks ties by scanning the sorted labels from closest to farthest:

counts = {0: 0, 1: 0, 2: 0}
for l in labels:
    counts[l] += 1
max_votes = max(counts.values())
winners = [cls for cls, count in counts.items() if count == max_votes]
if len(winners) == 1:
    return winners[0]
for l in labels:
    if l in winners:
        return l

predict_knn() computes distances to every training row, sorts them, and votes on the top k:

for d in X_test:
    distances = sorted(
        [(minkowski(dt, d, p), wt) for dt, wt in zip(model["X"], model["y"])],
        key=lambda x: x[0],
    )
    topk = distances[:k]
    predictions.append(voting([wp for (_, wp) in topk]))

Pipeline interface: train_knn() and predict_knn() are called directly by the training and evaluation modules.

Notes and references

  • KNN is a lazy learner: train_knn() only saves the training set, and every prediction scans all 830 training rows.
  • Because all 10 features are already expenditure percentages on the same 0–100 scale, no extra feature normalization is needed, though every feature is weighted equally in the distance sum.
  • Implemented from scratch in src/knn.py with minkowski(), voting(), train_knn(), and predict_knn().

C4.5 Decision Tree

Idea

A decision tree classifies information through splitting data based on its feature values to create a tree-like structure of decisions, from the root node all the way to a leaf at a specified depth. Each leaf node represents a predicted income tier.

How it works

The C4.5 Decision Tree builds itself through:

Step 1 - Initializing the Root Node: The root node here represents the whole dataset.

Step 2 - Calculating the Entropy: Entropy for a decision tree measures the amount of randomness or the "impurity" in a dataset. It is computed with the following formula: H(Dataset) = -Σpᵢlog₂(pᵢ)

Step 3 - Calculating the Information Gain: Information is calculated for each attribute to measure how much entropy decreases for each split. It is computed with the following formula: Information Gain = H(D) - ∑(|Dv|/|D|) · H(Dv)

Where D is the dataset, Dv is the subset v of the dataset, |Dv| is the number of samples in subset v, and |D| is the total number of samples in the dataset.

Step 4 - Calculating Split Information: Split Information measures how the dataset is distributed after splitting. It is computed with the following formula: Split Information = −Σ(|Dv|/|D|) · log₂(|Dv|/|D|)

Step 5 - Calculating the Gain Ratio: The Gain Ratio is used to normalize Information Gain to avoid bias towards attributes with many distinct values. It is computed with the following formula: Gain Ratio = Information Gain / Split Information

Step 6 - Selecting the Best Attribute and Split: The attribute with the highest gain ratio and the dataset is then divided into subsets based on its values.

Step 7 - Repeat recursively: Continue the process until the nodes become "pure" (Entropy = 0) or no attributes remain.

How we implemented it

train_dt() initializes a C45DecisionTree class (representing the root node) based on the given parameters X_train, y_train, features, min_samples, max_depth before calling def fit() to start the recursive process.

def best_threshold() returns the best attribute to split on along with calculating the Information Gain, the Split, and the Ratio given the entropy from def entropy().
