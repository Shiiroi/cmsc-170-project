Pipeline in Depth

Every step of our machine learning pipeline, what it does, and where it is in the code. Click a step to jump to it. (Adapted from Thanri et al., 2026, Figure 1.)

main.py runs every step in order; each step's output is the next step's input:

raw_rows            = data_collection()                  # prepare_dataset.py
cleaned_rows        = data_cleaning(raw_rows)            # prepare_dataset.py
dataset             = data_preprocessing(cleaned_rows)   # prepare_dataset.py
train_set, test_set = split_data_set(dataset)            # data_utils.py
models              = model_training(train_set)          # training.py
results             = model_evaluation(models, test_set) # evaluation.py

1. Data Collection

What it does: Reads the raw PSA table (2023 FIES, Table 7) and finds the header row with the 10 decile columns.

Input → output: raw CSV file → raw rows: (area, category, [10 decile values])

Where in the code: prepare_dataset.py → data_collection() 

for row in reader:
    if header is None:            # skip the title rows until the 10 decile columns are found
        ...
        continue
    values = []
    for d in range(1, 11):
        values.append(row[deciles[d]])
    raw_rows.append((row[area_idx].strip(), row[cat_idx].strip(), values))

The decile columns are found by name, not position, so the code still works if PSA adds or moves a column.

2. Data Cleaning

What it does: Removes rows that are totals of other rows, and cleans area and category names.

Input → output: raw rows → cleaned rows (same format)

Where in the code: prepare_dataset.py → data_cleaning(), is_regional_or_national(), clean_area(), clean_cat()

  • Aggregates removed: the Philippines total, the 18 regions, and the old combined Maguindanao (its totals equal del Norte + del Sur exactly). Keeping them would count the same families twice.
  • Names cleaned: leading dots, footnote marks (e.g. 1/), extra spaces, and broken "ñ" characters.
for raw_area, raw_cat, values in raw_rows:
    if is_regional_or_national(raw_area):
        continue
    cleaned_rows.append((clean_area(raw_area), clean_cat(raw_cat), values))

3. Data Preprocessing

What it does: Keeps the 10 expenditure groups, turns the 10 decile columns into rows, and labels each row with its income tier.

Input → output: cleaned rows → dataset = {X (1,180 × 10), y, areas, deciles, features}, also saved as data/processed/table7_cleaned.csv

Where in the code: prepare_dataset.py → data_preprocessing(), get_tier()

  1. Select features: keep only the 10 expenditure groups.
  2. Reshape: one row per (area, decile): 118 areas × 10 = 1,180 rows.
  3. Label: deciles 1–3 → Low (0), 4–7 → Middle (1), 8–10 → High (2).
for area in areas:
    for d in range(1, 11):
        r = [area, d]
        for col in feature_names:
            r.append(data[area][d][col])
        r.append(get_tier(d))
        out_rows.append(r)

The decile is used only to make the label; it is never a feature, since that would give away the answer.

4. Split Data Set

What it does: Splits the data 70/30 by area, at random with a fixed seed (42).

Input → output: dataset (1,180 rows) → train_set (830 rows, 83 areas) + test_set (350 rows, 35 areas)

Where in the code: data_utils.py → split_data_set(), split_by_area() 

unique_areas = sorted(set(areas))       # same starting order every run
rng = random.Random(seed)               # fixed seed → same split every run
rng.shuffle(unique_areas)               # shuffle AREAS, not rows
n_test = round(len(unique_areas) * test_ratio)
test_areas = set(unique_areas[:n_test])

Why by area: each area has 10 related rows (one per decile). Splitting by row would put some of an area's deciles in training and others in testing, so the model would be tested on areas it had already seen.

5. Model Training

What it does: Trains all three methods on the same training set.

Input → output: train_set → models (one trained model per method)

Where in the code: training.py → model_training(), which calls each method's train_x()

Every method exposes the same two functions, so model_training() and model_evaluation() treat all three the same way: 

model       = train_x(X_train, y_train, settings)   # learn from the training set
predictions = predict_x(model, X_test)               # used in Evaluation
def model_training(train_set):
    X, y, features = train_set["X"], train_set["y"], train_set["features"]
    return {
        "Gaussian Naive Bayes": train_nb(X, y, var_smoothing=1e-9),
        "KNN":                  train_knn(X, y, k=5, p=2),
        "C4.5 Decision Tree":   train_dt(X, y, features, min_samples=10, max_depth=10),
    }

Hyperparameters

All settings are passed in model_training(), so they are in one place.

Method Hyperparameter Value Meaning
Gaussian Naive Bayes var_smoothing 1e-9 Added to every variance so it is never 0 (dividing by 0 would break the Gaussian formula)
KNN k 5 Number of nearest neighbors that vote; odd, to reduce ties
p 2 Minkowski power: 1 = Manhattan, 2 = Euclidean distance
C4.5 Decision Tree max_depth 10 Most questions the tree asks before answering
min_samples 10 A node with fewer training rows is not split further

6. Model Performance Evaluation

What it does: Predicts the test set with every model and scores all of them with the same metrics.

Input → output: models + test_set → results (predictions + metrics per method)

Where in the code: evaluation.py → model_evaluation(); metrics in metrics.py

For each trained model, model_evaluation() predicts the test set and scores the predictions with the same metric functions from metrics.py:

for name, model in models.items():
    pred = PREDICT[name](model, test_set["X"])       # predict_nb / predict_knn / predict_dt

    precision = get_precision(y_test, pred)          # per tier
    recall    = get_recall(y_test, pred)             # per tier
    f1        = get_f1_score(precision, recall)      # per tier

    results[name] = {
        "predictions": pred,
        "accuracy":  accuracy_metric(y_test, pred),
        "precision": get_weighted_mean(precision, counts),
        "recall":    get_weighted_mean(recall, counts),
        "f1":        get_weighted_mean(f1, counts),
    }

The test set is used only here, once, after training. What each metric means: Metrics in depth → · Each model's results: Methods in depth →
